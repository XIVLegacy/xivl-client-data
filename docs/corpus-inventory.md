# Corpus Inventory

This page groups the FFXIV 1.23b CSV corpus from extraction
`2012.09.19.0001` by filename family. The complete row-by-row inventory is in
`manifests/tables.json`, regenerated by `tools/build-manifest.ps1`.

## Summary

- File count and total bytes: `manifests/manifest.json` is exact.
- Source extraction version: `2012.09.19.0001`.
- Reproduction command: `xivl extract "<game directory>" --output csv`.
- Matching extraction tool: [xivl-tools](https://github.com/XIVLegacy/xivl-tools).
  Its static sheet support status
  was `partial` only because malformed whole document conformance was
  incomplete. The frozen retail extraction and optional absent language
  blocks were verified.
- A verified retail re-extraction produced 803 files from 803 sheet documents
  and 183,678 rows. All 803 files matched the tracked corpus byte-for-byte.
- The complete byte-identical snapshot is stored privately as one deterministic
  ZIP. Maintainers normally hydrate it outside the checkout, set
  `XIVL_CSV_DIR`, and run the repository checks against that root:

  ```powershell
  $csvDir = Join-Path $env:TEMP "xivl-client-data-csv"
  python tools\private_csv_corpus.py verify <path-to-csv.zip>
  python tools\private_csv_corpus.py hydrate <path-to-csv.zip> $csvDir
  $env:XIVL_CSV_DIR = $csvDir
  python tools\validate_corpus.py
  ```

  Hydration requires the destination to be absent or empty. Every corpus
  consumer also accepts `--csv-dir <path>`; the environment variable is the
  convenient default for a maintainer session. An existing repository-local
  `csv/` directory is only a backward-compatible cache, and normal public
  checks do not fetch the archive.
- The extractor reported 639 missing trailing values, 195 absent blocks, and
  57 conflicting values. These counts are the reproducibility fingerprint.
- Record a future extraction as a new versioned corpus with its own provenance,
  then regenerate its manifests and reconcile it against prior versions.

## Localization

`xtx_*.csv` (59 files) is the localized text layer for UI, commands, NPCs,
achievements, and system messages. It explains integer IDs stored by the
gamedata tables and carries Japanese, English, German, and French columns.

- `xtx_itemName.csv`: col 4 = Japanese name, col 5 = English Title (the
  column `tools/mappings/items.py` copies), col 6 = lowercase English
  variant used in inline grammar.
- `xtx_achievement.csv`: cols 6-10 are the locale block (Japanese title,
  Japanese description, English title, English description, German title);
  `tools/mappings/achievement.py` copies col 8 (English title).

## Duplicate variants

Files with a `(2)` suffix are separate extraction outputs, not duplicates.
Keep them separate until reconciliation proves that their rows can merge.

## Unused trailing columns

Some sheets carry unused trailing columns. These are extras in the decoded
structures:

- `itemData.csv`: col 42 (between rarity col 41 and isUseable col 43) and
  col 62 (between recastTime col 61 and recastGroup col 63) are unused s32
  and float positions.
- `actorclass_graphic.csv`: 41 typed s32 columns (6-46). Columns 45 and 46 are
  trailing extras with no known client-sheet purpose.

## Coverage gaps

Small singleton files remain outside these families. Use the
manifest and the relevant evidence record when a long-tail table is promoted.
Do not expand this navigation page into a row-by-row catalog.
